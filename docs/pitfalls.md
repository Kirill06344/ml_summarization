# Ловушки

Всё ниже действительно случилось при работе над проектом или проверено на аккаунте в прошлых работах.

## Метрика и данные

- Стандартный `rouge_score` даёт ноль на нелатинских языках: он оставляет только `[a-z0-9]`.
- `load_dataset('GEM/xlsum')` зависит от загрузочного скрипта датасета. Просмотр на Hugging Face из-за него отключён, поэтому
  архивы читаются напрямую.
- Лимит резюме 84 токена из настроек авторов срезает 32% вьетнамских эталонов: токенизатор mT5 дробит вьетнамский сильнее.
- Быстрый токенизатор mT5 не умеет byte fallback и иногда даёт `<unk>` там, где медленный даёт байтовые токены. Замер на 300
  текстах каждого языка: 18 таких токенов из 132 773 в китайском, ноль в остальных. Цена приемлемая, выигрыш скорости втрое.

## mT5 и обучение

- **fp16 даёт NaN с первых батчей.** Веса выходного слоя `wo` настолько велики, что его выход не помещается в fp16. Первый
  нечисловой выход локализован на `decoder.block.2.layer.2.DenseReluDense.wo` на настоящих весах `google/mt5-small`, на случайных
  весах ошибка не воспроизводится. Библиотека держит `wo` в fp32 только при `model.half()`, но не при autocast. Решение —
  `keep_feed_forward_output_in_fp32`. Первая гипотеза про `MT5LayerNorm` оказалась неверной: там дисперсия уже считается в fp32.
- Патч слоя нужно делать подменой класса: `MethodType` при копировании модуля продолжает считать на весах оригинала.
- `DataParallel` не годится для mT5-base: сбор градиентов на первой GPU поверх весов и состояния Adam приводит к OOM. Нужен
  `DistributedDataParallel`.
- Логиты полного батча занимают около гигабайта: словарь 250 тысяч. Голову надо применять только к настоящим токенам.
- Если процессы по-разному решат, пропускать ли батч, обучение зависнет. Такие решения должны быть общими.

## Kaggle

- Датасет монтируется в `/kaggle/input/datasets/<user>/<slug>`, а не в `/kaggle/input/<slug>`. Данные ищутся по манифесту.
- **`datasets status` отвечает `ready` и про прошлую версию**, поэтому готовность определяется по файлу с хэшем в имени. Проверка
  `--expect-code-hash` поймала это и спасла от обучения старым кодом.
- Образ меняется без предупреждения: `transformers` 5.16 и Python 3.13 на момент работы. Локальная версия должна совпадать.
- Новая версия кода, залитая, пока ядро стоит в очереди, досталась бы ему: ядро читает датасет при старте, а не при отправке.
- Сетевой сбой CLI — это не падение ядра: статус берётся только из явного `KernelWorkerStatus`.
- При `spawn` процессы импортируют файл ядра заново, поэтому вызов `main` в стабе нужен под `if __name__ == '__main__'`.
- Глобальный `KAGGLE_API_TOKEN` молча уводит операции на другой аккаунт, поэтому инструменты удаляют его из окружения.

## Инструменты

- `pgrep -f <шаблон>` в ожидающем скрипте находит сам этот скрипт и никогда не завершается.
