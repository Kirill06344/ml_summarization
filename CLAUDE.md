# Правила работы над проектом

Многоязычная суммаризация новостей на XL-Sum (курсовая). Итоговый отчёт — [README.md](README.md), вход в документацию —
[docs/README.md](docs/README.md). Этот файл — рабочие правила, не журнал результатов.

## Инварианты

- Языки — только `src/languages.py`. Разбиение — официальное, val и test не меняются; очистка затрагивает только train.
- Вход модели и эталоны идут через `src/data.py`, метрика — только через `src/metrics.py`. Стандартный `rouge_score`
  нельзя применять к нелатинским языкам: он отдаёт ноль.
- Модель и эпоху выбирают только по val. Test оценивается один раз, по правилам [протокола](docs/experiment_protocol.md).
- Числа в отчёте получаются из `runs/*/scores_*.json` через `tools/score.py` и `tools/collect_results.py`, а не вручную.
- Новый рецепт или сид — новый YAML и новый слаг; конфиг завершённого прогона не переопределять.

## Окружение

- Python только из `.venv`. Локальная версия `transformers` должна совпадать с образом Kaggle по мажорной версии.
- Обучение — Kaggle, две T4, аккаунт `badzhik`, токен `~/.kaggle/access_token`. Прочие токены не использовать, значения не
  печатать, `KAGGLE_API_TOKEN` глобально не экспортировать. Датасеты и ядра — только приватные.
- Перед запуском ядра — `pytest` и `--dry-run`; квоту и активные ядра проверять перед запуском. Не больше двух ядер сразу.
- `src/` хэшируется: пока ядра ждут в очереди, код не менять. Готовый результат — `--fetch-only`, а не повторное обучение.
- Данные, веса, прогнозы и токены в git не попадают.
