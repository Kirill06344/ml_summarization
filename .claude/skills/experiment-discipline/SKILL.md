# Дисциплина эксперимента

Работать из корня репозитория. Сначала прочитать `CLAUDE.md` и [протокол](../../../docs/experiment_protocol.md).

## Перед запуском

1. Записать гипотезу, предсказание и действие по результату в протокол **до** обучения.
2. Создать YAML в `configs/experiments/`, поле `note` обязательно. Одно отличие от контроля, кроме заранее записанных.
3. Сверить фактические ключи: `tools/kaggle_train.py --config <yaml> --dry-run`.
4. Выполнить `pytest`. Изменение обучения проверять и тестом в двух процессах: на GPU рассинхрон выглядит как зависание.
5. Посчитать цену по последнему замеру скорости и сверить с бюджетом протокола. Проверить, нет ли ядер в очереди:
   новая версия кода досталась бы им и уронила проверку хэша.

## Как сравнивать

- Только один набор документов: `stable_subset`, 500 на язык на val. Главная метрика — macro ROUGE-2.
- Парный bootstrap: `tools/score.py --against <контроль>`. Эффект есть, если CI не содержит нуля и |Δ| ≥ 0,3 п.
- CI описывает выборку документов, но не разброс запусков: при одном сиде вывод об обучении ограничен этим сидом.
- Сравнивать также языки по отдельности: рост среднего может скрывать провал одного языка.
- Сверять с таблицей авторов можно только языки без стеммера в их скорере (индонезийский, вьетнамский).

## Kaggle при задержках

`RUNNING` не значит, что начался Python-код; пустой лог не доказывает зависание. Ошибка DNS или CLI — не падение ядра:
смотреть явный статус. Результат забирать `--fetch-only`, неизвестный статус — не повод обучать заново.

## После опыта

Сверить `training_log.json` с рецептом: код, число шагов, `overflowed_steps`, `skipped_batches`, причину остановки.
Числа — через `tools/score.py`, в результаты — через `tools/collect_results.py`. Отрицательный результат записать с областью
проверки: модель, данные, сид, параметры. Отклонения от плана — в раздел «Отклонения» протокола.
